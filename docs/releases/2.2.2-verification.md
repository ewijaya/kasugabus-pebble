## Problem fixed

With timetable v4 (18 boarding points) the owner's phone settings lacked
Nihon Teien-mae and Handai Honbu-mae. Settings waited 2 seconds for the
watch's boarding-point list and otherwise used the list bundled with the app
(the 15-point baseline). Watch favourites for the new stops would then appear
as unavailable and block saving.

## Change

Settings wait up to 8 seconds (opening as soon as the list is complete), the
last complete list is remembered on the phone (`src/pkjs/catalog-store.js`),
and with no list available, IDs the watch already uses stay selectable as
"Stop #N (name not loaded)" so saving is never blocked.

## Checks

- Consolidated automated suites, including `tests/test_phone_catalog.js`:
  live list remembered; slow watch falls back to the remembered list; with no
  list, new-stop favourites stay saveable and are preserved.
- Clean Emery build; emulator launch, navigation and all seven
  update-transfer scenarios on the exact PBW.
- Physical: installed through Dev Connection (watch and phone code) before
  approval. The owner approved publication; a specific result of the phone
  settings check was not reported.
