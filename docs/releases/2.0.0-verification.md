# KasugaBus 2.0.0 verification — in progress

Version 2.0.0 combines larger text (Large by default), four themes, clearer
Nearby controls, bus-number browsing, All departures and the local-area banner.
Version 1.0.0 remains the published release until a new exact candidate is
physically installed, approved and published. No 2.0.0 publication is claimed
by this working report.

## Completed implementation checks

- Preferences preserve the existing 80-byte packet and atomic control banks.
  Schema 1 migrates to Large and its corresponding dark theme; all twelve
  appearance combinations and interrupted writes have portable tests.
- Phone tests cover manual-only and startup Nearby, disabled location,
  settings validation, no GPS from ordinary settings open/save, and distinct
  accuracy/permission/timeout/availability states.
- Saved home uses private phone storage. Explicit Save requires acknowledged
  durable settings, and explicit Clear works while location is off. Privacy
  tests inspect actual configuration URLs/meta, watch messages and app logs
  for leakage. Home never enters the timetable or app-release data.
- Bus-number tests reconcile all eight operator/number keys and all 120
  point/route membership combinations against the reviewed production JSON.
- Merged schedule tests compare native C output with an independent JSON
  oracle: time/distance ties, unknown distances, Due-minute boundaries,
  operator-specific calendars and validity, holidays, overrides, service
  bounds, cached future revisions, overnight trips and removed points.
- The All selection journal preserves explicitly empty selections and tests
  every incomplete-write boundary. Resource-backed baseline storage tests
  current/future alternation, corruption recovery and interrupted transfers.
  Portable C suites also pass AddressSanitizer and UndefinedBehaviorSanitizer.

The latest consolidated intermediate run passed 175 Python tests, 43 phone
scenarios, 16 Clay/index checks, 5 real-HTTP feed checks and the portable C suites.
Saved-home notification tests now cover failed delivery, restart, reconnect,
overlapping Save/Clear and storage failure. Native queue/focus tests exercise
the actual C function bodies, including obsolete-request retries and retaining
equal-time trips after a selected departure disappears. These checks include
the final application changes; a clean source-bound build remains required.
These counts describe this checkpoint, not a frozen-candidate certificate.

## Native preview findings

Preview `f7e4ec85b5bc98b8c2d2a7bd90a87bab43f5643a830ad4683c7d84b888d53808`
(854,383 bytes) predates the complete All departures UI and final memory
integration. Its native 200×228 captures preserve actual emulator rendering.
Nine appearance combinations completed before one missing UI-log pair stopped
Data status scrolling in Extra Large / Neon Light. Preferences and real clock
were restored. A focused repeat reached the full 899-pixel scroll limit with
normal native logs; the harness is being made tolerant of a single missing
proof via an explicit redraw, without repeating a selection click.

The disabled-location guidance initially disappeared on repeat redraw despite
unchanged geometry. Drawing the document with an unconstrained WordWrap canvas
while bounding navigation by its measured content fixed this in native
Standard, Large and Extra Large captures. The final matrix must include it.

Review also identified the need to retain selected boarding/trip identity
when incoming distances reorder rows, retain local/JST clock context in the
compact Extra Large Home, and recover a lost saved-home-change notification.
Those corrections belong to the same 2.0.0 candidate and its final checks.

The integrated preview `db224d5adb9f1075b78c283703efc35f8f5f19de7ac7cca9da5565ee82f06883`
(871,187 bytes) launches with 40,028 bytes free heap. Native probes show the
Extra Large 12:55 clock, date/LOCAL context, explicit Scheduled label, Due,
operator/number, and the full scrolled stop/direction/distance text. These
are preliminary observations; final transfer/font paths still need measurement.

One install attempt stalled in the SDK emulator before KasugaBus started.
Bounded GDB evidence found the firmware App Fetch task and a flash-logging
erase/semaphore wait, with no KasugaBus task. Restarting only the recorded
Emery emulator/relay while preserving flash restored installation and retained
the All selection journal and active dataset. The fixture relay guard is being
strengthened to require a native app response after restoration. No physical
watch result is inferred from this emulator failure or recovery.

A later relay-only restoration had a different result: the firmware and
KasugaBus tasks were healthy, but the immediate native STATE health probe
timed out during startup. Subsequent ordinary and guarded STATE probes both
returned schema 2 / active dataset 2 / no pending dataset, and native Ping
succeeded without restarting or reinstalling. Restoration now uses a bounded
retry for this transient timeout; an identity mismatch still fails immediately.
The earlier failed probes remain recorded rather than counted as passes.
Preview PNGs are retained under `.release/preparation/preview-screenshots/`
with a relocation map; final bulk captures use the ignored `verify-` prefix.

The clean `b3daaf9` PBW (`2dc01ca8…`, 871,203 bytes) completed the native
All departures fixtures and all twelve appearance combinations, producing
105 captures. Selection/reference/preferences, real clock and the normal SDK
relay were restored. The first run had stopped on a missing menu-transition
proof; a focused repeat and the complete rerun succeeded, with raw native
events retained. Visual review found that the two-line header could lose its
Scheduled/JST line after scrolling. The subtitle now uses the same generous
drawing canvas as long guidance, while retaining measured layout dimensions;
ordinary and route-filtered boards also retain a Scheduled/JST label at every
size. The revised PBW still requires native confirmation and final auditing.

## Required before candidate approval

- Finish integration review and rerun the complete tests and clean Emery build.
- Measure actual final-PBW heap across launch, navigation and a full update.
- Run and inspect the full size/theme matrix, bus-number flow and All departures
  selection, sorting, explicit location states, offline fallback and restart.
- Run current/future, interrupted-transfer and recovery checks, then prove the
  unchanged final phone worker receives production dataset v2 over HTTPS.
- Freeze one source-bound PBW, install it physically and request approval of
  its exact digest, destinations and reviewed listing/banner/screenshots.

The latest bounded physical Dev Connection probe responded successfully.
No 2.0.0 physical installation or approval is implied by that connectivity check.

Broader physical GPS/permission, connection-loss/update-recovery, outdoor
readability, battery and seven-day use remain outstanding. Earlier Time 2,
Poco F4 / Android 14 / companion 1.14.0.1 results belong to the exact 1.0 artifacts
recorded in the existing verification report. They do not certify 2.0.0.
